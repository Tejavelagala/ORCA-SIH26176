# ORCA — SIH 2026 PS-26176

**Marine EcOsystem Reasoning with Collaborative Agents**

ORCA is a conversational multi-agent marine decision-support prototype. It combines Ocean, Weather and Geo agents with a deterministic Risk Engine so the safety state is computed from explicit rules rather than generated by an LLM.

## MVP capabilities

- Conversational marine query handling
- Parallel Ocean, Weather and Geo agents
- Live Open-Meteo weather/marine integration with transparent demo fallback
- INCOIS PFZ advisory metadata adapter
- Configurable GeoJSON GIS layers
- Deterministic risk states: SAFE, CAUTION, UNSAFE, BLOCKED and DATA_UNAVAILABLE
- Explainable risk factors, reasoning trace and data provenance
- Prototype PFZ route/bearing visualization
- Leaflet marine map
- English, Telugu and Hindi response selection
- Browser voice input/output
- One-click deterministic SIH demo scenarios
- PPT-aligned Mission Modes for Fisher, Ship Operator, Coast Guard and Disaster Team
- Opt-in Marine Alert Watch using periodic prototype risk checks
- Public source gateways for INCOIS PFZ, INCOIS Ocean State Forecast, IMD Marine and MOSDAC

## SIH presentation demo

Start both servers, then use the frontend:

1. Ask a normal marine question.
2. Select a **Mission Mode**:
   - Fisher
   - Ship Operator
   - Coast Guard
   - Disaster Team
3. Show the **6-Stage ORCA Reasoning Trace**.
4. Show **Evidence → Rules → Decision → Route**.
5. Run the deterministic scenarios:
   - **SAFE** — normal prototype conditions
   - **CAUTION** — elevated prototype wind condition
   - **UNSAFE** — high prototype wave condition
   - **BLOCKED** — restricted-zone condition
   - **DATA GAP** — critical wave data unavailable
6. Start **Presentation Mode** to cycle through the five states.
7. Show the map, route reference and provenance.
8. Optionally enable **Marine Alert Watch** to demonstrate periodic prototype risk checks.
9. Open the source gateways if a judge asks about the evidence ecosystem.

These scenarios call the same deterministic Risk Engine used by the application. They are presentation scenarios, not real navigation advice.

## Mission Modes

Mission Modes are a frontend use-case layer over the same ORCA query workflow:

- **Fisher:** PFZ, sea-state, weather and geographic restriction brief.
- **Ship Operator:** marine conditions, ocean evidence and route context.
- **Coast Guard:** hazards, restricted zones, weather and ocean evidence.
- **Disaster Team:** hazards, weather, ocean conditions and data limitations.

They are presentation-oriented workflows in the current prototype; they do not represent four separate backend agent pipelines.

## Marine Alert Watch

Alert Watch is an **opt-in prototype monitor**. It performs a risk check for the selected location immediately and then approximately every 60 seconds while enabled.

It is currently browser-side polling, not a production push-notification or background alert infrastructure.

## Current data/provenance model

- **Weather/marine:** Open-Meteo is used for the prototype live weather and wave integration.
- **INCOIS:** the official PFZ advisory page can provide live advisory metadata when reachable.
- **PFZ geometry:** remains explicitly marked as demo geometry until an approved machine-readable authoritative geometry feed is configured.
- **GIS:** configurable GeoJSON layers can be evaluated with Shapely; without configured authoritative layers the Geo Agent reports the limitation rather than inventing a boundary result.
- **IMD:** a configurable marine-warning adapter exists, but an authoritative IMD endpoint must be configured for live warning integration.
- **LLM:** optional; when unavailable, ORCA uses a deterministic explanation fallback.

## Judge-facing 2-minute demo script

**Opening — 20 seconds**

> "ORCA is a conversational marine decision-support prototype. Instead of asking an LLM to make a safety decision, ORCA collects evidence through specialized Ocean, Weather and Geo agents and passes that evidence to a deterministic Risk Engine."

**Live query — 30 seconds**

Ask:

> "Is it safe to fish near Kakinada tomorrow morning?"

Point to the three agents and then show:

**Evidence → Rules → Decision → Route**

**Safety scenarios — 50 seconds**

- **UNSAFE:** show the high-wave scenario and point to the deterministic threshold.
- **BLOCKED:** show the restricted-zone scenario and point to the geographic rule.
- **DATA GAP:** show missing wave data and explain that the engine does not silently return SAFE.

**Close — 20 seconds**

> "The prototype explicitly distinguishes provider data, demo geometry and unavailable authoritative layers. The decision trace shows what evidence was available, which deterministic rule fired, and how the final explanation was produced."

## Architecture answer for judges

> “ORCA does not ask an LLM to decide whether a marine situation is safe. Specialized agents collect evidence from ocean, weather and geographic sources. A deterministic Risk Engine evaluates explicit rules. The language model, when configured, is only used to explain the already-computed result.”

## What not to claim

- Demo PFZ coordinates are live INCOIS PFZ geometry.
- The straight-line prototype route is a navigational route.
- Prototype thresholds are official maritime safety regulations.
- An unavailable provider is live.
- Alert Watch is a production push-alert service.
- Mission Modes are separate backend agent pipelines.
- Prototype output is authoritative navigation or safety guidance.

## Optional environment configuration

Copy `.env.example` to `.env` and configure only the providers you have access to:

```env
LLM_API_KEY=
LLM_MODEL=
LLM_API_URL=https://api.openai.com/v1/chat/completions
WEATHER_PROVIDER=open-meteo
IMD_MARINE_URL=
INCOIS_PFZ_URL=
GEO_LAYERS_PATH=
```

Without an LLM key, ORCA uses its deterministic explanation fallback. The LLM never changes the Risk Engine result.
